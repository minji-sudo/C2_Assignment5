# [과제 05] 순차 탐색과 BST 탐색 성능 비교

## 1. 실험 방법
0~1000 범위에서 중복 없는 난수 100개를 뽑아 배열과 이진 탐색 트리(BST)에 각각 저장했다. 그다음 탐색 키 50개를 정해 두 자료구조에서 같은 키를 찾으면서 비교 횟수를 셌다. 
BST는 만드는 데에도 비교가 들기 때문에 생성 단계의 비교 횟수도 따로 측정했다. 탐색 키는 0~1000 범위에서 난수로 50개를 추출하여 배열에 존재하는 값과 존재하지 않는 값이 자연스럽게 섞이도록 하였다.

## 2. 결과

| 항목 | 순차 탐색 | BST 탐색 |
| :--- | :---: | :---: |
| **50회 총 비교 횟수** | 3,412 | 418 |
| **1회 평균** | 68.24 | 8.36 |
| **생성 시 비교 횟수** | 0 | 586 |

* 수치는 1회 실행 결과 기준이며, 난수에 따라 오차가 발생할 수 있다. 반복 실행 시에도 순차 탐색 평균 65~70회, BST 탐색 평균 8~9회 수준을 유지했다.

## 3. 분석 및 고찰

* **탐색 성능**: 순차 탐색은 앞에서부터 하나씩 비교하므로 O(N)이고, 평균 68회가 나왔다. BST는 비교할 때마다 탐색 범위가 줄어들어 O(log N)에 가깝고, 평균 8회였다. 단일 탐색 기준으로 BST가 약 8배 적게 비교했다.
*  순차 탐색 평균이 N/2인 50보다 다소 높게 나온 것은 탐색 키 50개 중 배열에 없는 키가 포함되어, 배열 전체(100회)를 끝까지 훑고 실패한 경우가 많았기 때문이다.
* **생성 비용 고려**: 배열은 저장 시 비교 연산이 없지만, BST는 100개 노드를 삽입하며 586회의 사전 비교가 발생했다. 탐색 1회당 약 60회(68.24 - 8.36)의 비교를 아끼므로, 586 / 60 ≈ 9.77, 즉 탐색을 10번 정도 수행하면 생성 비용이 상쇄된다.
* 이번 실험은 50번 탐색이라 BST가 훨씬 이득이었지만, 탐색을 한두 번만 하고 끝나는 환경이라면 배열을 쓰는 편이 낫다.
* **한계 및 발전 방향**: 이번 실험은 난수 입력이라 트리가 어느 정도 균형을 이뤘지만, 이미 정렬된 데이터를 순서대로 넣으면 한쪽으로만 뻗는 편향 트리가 된다. 이 경우 탐색은 O(N), 생성은 O(N^2)까지 나빠져 BST의 장점이 사라진다. 실제 정렬된 배열을 넣어 테스트해보니 탐색 성능이 순차 탐색과 차이가 없어짐을 확인할 수 있었다. 이를 막으려면 AVL 트리나 Red-Black 트리처럼 스스로 균형을 잡는 자위적 균형 트리가 필요하다.
