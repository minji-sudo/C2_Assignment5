# [과제 05] 순차 탐색

## 1. 실험 방법
탐색 키는 데이터와 상관없이 0~1000 범위에서 난수로 50개를 뽑았다. BST는 만드는 데에도 비교가 들기 때문에 생성 단계의 비교 횟수도 따로 측정했다.
데이터가 100개뿐이라 키의 약 90%는 배열에 없는 값(탐색 실패)이고, 일부만 탐색에 성공한다. 그래서 순차 탐색은 실패한 경우 배열 전체를 훑게 되어 평균 비교 횟수가 N/2보다 크게 나온다.

## 2. 결과

| 항목 | 순차 탐색 | BST 탐색 |
| :--- | :---: | :---: |
| **50회 총 비교 횟수** | 3,412 | 418 |
| **1회 평균** | 68.24 | 8.36 |
| **생성 시 비교 횟수** | 0 | 586 |

* 수치는 1회 실행 결과 기준이며, 난수에 따라 오차가 발생할 수 있다. 반복 실행 시에도 순차 탐색 평균 65~70회, BST 탐색 평균 8~9회 수준을 유지했다.

## 3. 분석 및 고찰


- **탐색 성능.** 순차 탐색은 O(N)이고 평균 68.24회가 나왔다. 탐색에 성공하는 경우만 보면 평균이 N/2 = 50회여야 하는데, 키가 0~1000 난수라 대부분 배열에 없는 값이고 그 경우는 100회를 전부 비교하기 때문에 훨씬 높게 나왔다 .
- BST는 O(log N)에 가깝고 평균 8.36회로, 순차 탐색보다 약 8.16배 적게 비교했다.
- **생성 비용.** BST는 100개를 넣는 데 586회 비교가 들었다. 탐색 한 번에 약 59.88회를 아끼니까 586 ÷ 59.88 ≈ 9.79, 즉 탐색을 10번 넘게 하면 생성 비용을 회수한다. 한두 번만 찾고 끝나는 상황이면 배열이 낫고, 이번처럼 50번 찾으면 BST가 이득이다.
- **한계.** 정렬된 데이터를 순서대로 넣으면 트리가 한쪽으로만 뻗어서(편향 트리) 탐색은 O(N), 생성은 O(N²)까지 나빠진다. 이를 막으려면 AVL이나 Red-Black 트리처럼 스스로 균형을 잡는 트리가 필요하다.
